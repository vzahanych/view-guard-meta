refactor(iot): implement device-agnostic service architecture

Refactor IoT service to a clean, device-agnostic architecture following
vm-gateway patterns. Extract components into dedicated packages, implement
DeviceRegistry with persistence, and establish unified service façade.

Key changes:
- Extract types: Move all interfaces and types to types/ package for clean
  separation of concerns
- Implement DeviceRegistry: Create complete device registry implementation
  with device storage, type/capability indexes, and lifecycle management
- Add persistence: Integrate meta-storage for device persistence with
  optional in-memory fallback
- Extract plugin-registry: Move plugin registry to dedicated package with
  plugin management and discovery coordination
- Reorganize structure: Create device-registry/ package with registry,
  persistence, and comprehensive tests
- Update CCTV integration: Refactor CCTV to use DevicePlugin interface,
  integrate with new registry system
- Remove old implementations: Delete device_state_machine.go,
  device_state_configs.go, and data_pipeline.go in favor of new structure
- Add comprehensive documentation: Create doc.go with architecture overview,
  package structure, and usage examples
- Enhance test coverage: Add registry tests, examples, and integration
  verification tests

Architecture improvements:
- Device-agnostic design: Service works with any device type (cameras,
  sensors, audio) through unified DevicePlugin interface
- Clean package structure: Top-level façade with subpackages for
  implementations (plugin-registry, device-registry)
- Persistence abstraction: DeviceStorageBackend interface enables
  pluggable storage backends
- Lifecycle management: Unified lifecycle coordination across all components
- Observability: HealthSnapshot() method provides service status visibility

This refactoring establishes a foundation for supporting multiple device
types while maintaining clean separation of concerns and testability.
